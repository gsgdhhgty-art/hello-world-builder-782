# تطوير الفواتير والتقارير والكتالوج واقتراحات AI وتنبيهات المخزون

## الهدف
تطوير الوحدات الحالية بدل إنشاء بدائل منفصلة، مع الحفاظ على واجهة SmartPOS العربية واتجاه RTL والصلاحيات بين المؤسسات.

## نطاق التنفيذ

### 1. الفواتير والطباعة الحرارية
- إعادة تنظيم شاشة تفاصيل الفاتورة لتعرض بيانات المتجر والعميل والكاشير والفرع، وجدول أصناف واضحًا يشمل الكمية والسعر والخصم والضريبة والإجمالي.
- توحيد معاينة الفاتورة بعد البيع ومعاينتها من سجل المبيعات حتى لا تختلف الأرقام أو طريقة العرض.
- إضافة إعداد عرض الورق الحراري 58 مم أو 80 مم، وتطبيق قواعد طباعة مخصصة تخفي عناصر النظام وتمنع قص الأعمدة.
- إظهار خطأ واضح إذا منع المتصفح نافذة الطباعة، مع إبقاء الطباعة عبر مربع الطباعة الأصلي المتوافق مع الطابعات الحرارية.

### 2. لوحة التقارير والتصدير
- تطوير لوحة التقارير لتشمل ملخص المبيعات، الضرائب، صافي الأداء، قيمة المخزون، المخزون المنخفض، والأصناف الأكثر مبيعًا.
- إضافة فلاتر موحدة للتاريخ والفرع والكاشير، وتطبيقها على كل الأرقام والجداول.
- إضافة رسوم بيانية مختصرة للمبيعات اليومية والأصناف الأعلى مبيعًا باستخدام مكتبة الرسوم الموجودة.
- إضافة تصدير CSV وExcel للنتائج المفلترة، مع استبعاد بيانات التكلفة والربح تلقائيًا ممن لا يملك صلاحيتها.
- نقل التجميعات الحساسة والكبيرة إلى وظائف قاعدة بيانات مؤمنة لتجنب نقص النتائج أو كشف تكلفة المنتجات في المتصفح.

### 3. إدارة الفئات والعلامات التجارية
- إنشاء شاشة مستقلة لإدارة فئات المنتجات والعلامات التجارية، مع البحث والإضافة وإعادة التسمية والحذف الآمن.
- إضافة جدول علامات تجارية مع عزل كامل لكل مؤسسة، وربط المنتج بعلامته التجارية.
- تحديث نموذج المنتج وقائمة المنتجات لدعم اختيار الفئة والعلامة التجارية والبحث والتصفية بهما.
- عند حذف فئة أو علامة مستخدمة، يطلب النظام نقل المنتجات أو إزالة الربط بوضوح بدل حذف بيانات المبيعات أو المخزون.

### 4. اقتراح المنتجات باستخدام Lovable AI
- إضافة نافذة داخل شاشة الكاشير يكتب فيها الموظف وصف طلب العميل بحرية.
- إنشاء وظيفة خادمية محمية تتحقق من هوية الموظف وصلاحيته، وتقرأ كتالوج مؤسسته فقط، ثم تستخدم `openai/gpt-6-astra` عبر Responses API المتدفق.
- إعادة اقتراحات منظمة تحتوي على معرفات منتجات حقيقية وأسباب مختصرة، والتحقق منها مقابل الكتالوج قبل العرض أو الإضافة للسلة.
- توفير زر إضافة لكل اقتراح، وحالات تحميل وخطأ واضحة، وتعطيل الميزة دون إنترنت من دون التأثير على البيع المحلي.
- تطبيق حدود لطول الطلب وحجم الكتالوج المرسل، وعدم إرسال بيانات العملاء أو الأسعار الحساسة غير اللازمة.

### 5. تنبيهات إعادة التوريد
- استخدام حد إعادة الطلب الموجود لكل منتج، مع إعداد عام لتفعيل التنبيهات وخيار تضمين المنتجات النافدة.
- إضافة جرس فعلي بعدّاد وقائمة منسدلة تعرض المنتجات المنخفضة حسب فرع/مستودع المستخدم.
- تطوير صفحة المخزون بقسم «تحتاج إعادة توريد» يعرض الرصيد والحد والعجز والكمية المقترحة للطلب، مع البحث والفرز والفلترة.
- تحديث التنبيهات بعد البيع والمشتريات والجرد، وعدم إنشاء إشعارات مكررة أو الاعتماد على بيانات قديمة.

## الأمان والبيانات
- إضافة migration واحدة للجداول والحقول والفهارس الجديدة مع GRANT ثم RLS وسياسات المؤسسة في الترتيب الصحيح.
- حماية تقارير الربح والتكلفة داخل قاعدة البيانات، وتشديد قراءة تفاصيل الفواتير لتطابق صلاحية عرض الفاتورة نفسها.
- عدم استخدام صلاحيات إدارية لاقتراحات AI؛ قراءة المنتجات تتم بهوية المستخدم وقواعد المؤسسة الحالية.

## التحقق
- إصلاح أي تشخيص قديم لمسار `use-mobile.tsx` والتأكد أن الاستيرادات تشير إلى الملف الحالي `use-mobile.ts`.
- اختبار TypeScript وESLint والاختبارات وبناء الإنتاج.
- إجراء طلب AI حقيقي والتحقق من الاستجابة ومعالجة أخطاء الاعتمادات/الرصيد دون إعادة محاولات غير آمنة.
- اختبار الفواتير والتقارير والفئات والتنبيهات وشاشة الكاشير على سطح المكتب والهاتف، وتجربة طباعة 58/80 مم وتصدير CSV وExcel.

## افتراضات معتمدة
- «الشركة» تعني العلامة التجارية وليست المورد.
- صيغ التصدير المطلوبة هي Excel وCSV.
- تنبيهات المخزون تظهر في جرس التطبيق وصفحة المخزون.
- الطباعة الحرارية تتم من خلال مربع الطباعة الأصلي للمتصفح؛ الطباعة الصامتة المباشرة تحتاج برنامج تشغيل محلي خارج نطاق تطبيق الويب.
