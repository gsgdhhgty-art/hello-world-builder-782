# نسخة الكاشير وإعدادات التسعير والربح

## الهدف
تطوير شاشة البيع الحالية إلى تجربة كاشير عملية على الهاتف وأجهزة نقاط البيع، مع إبقاء نفس كتالوج المؤسسة والمخزون، وفتحها تلقائيًا لموظفي الكاشير. توحيد إعدادات العملة والضريبة وطريقة حساب الربح بحيث تنعكس فورًا على البيع والتقارير.

## نطاق التنفيذ

### 1. إصلاح تشخيص الهاتف
- تثبيت استخدام الملف الحالي `use-mobile.ts` فقط مع الاستيراد المباشر لـ React hooks.
- البحث عن أي مرجع قديم إلى `use-mobile.tsx` أو إعداد بناء قديم وإزالته من المصدر ومسارات الفحص.
- إضافة اختبار بناء يمنع عودة التشخيص TS2686.

### 2. واجهة كاشير حقيقية للهاتف
- إعادة ترتيب شاشة البيع على الهاتف لتكون شاشة تشغيل كاملة: شريط بحث/باركود ثابت، أزرار مسح بالكاميرا وإدخال سريع، فئات أفقية، شبكة منتجات قابلة للمس، وعداد واضح لعدد الأصناف والإجمالي.
- إضافة شريط سفلي ثابت يعرض عدد القطع والإجمالي ويفتح سلة مدمجة لإتمام الفاتورة دون مغادرة شاشة البيع.
- إبقاء السلة والعدادات والدفع المختلط والطباعة والوردية والعمل بدون إنترنت مرتبطة بنفس منطق البيع الحالي، بدل إنشاء منطق موازٍ.
- الحفاظ على تخطيط سطح المكتب الحالي مع تحسينات تستهدف الشاشات الصغيرة وأجهزة الكاشير اللمسية فقط.

### 3. نسخة تشغيل مخصصة للكاشير
- اعتبار `/pos` واجهة الكاشير الأساسية التي تستخدم كتالوج المؤسسة ومخزون فرع الموظف نفسه.
- بعد تسجيل الدخول، يذهب دور `CASHIER` مباشرة إلى `/pos`، بينما تبقى أدوار الإدارة على لوحة التحكم.
- عند فتح التطبيق بجلسة كاشير قائمة، الانتقال مباشرة إلى `/pos` بدل الصفحة العامة.
- تبسيط غلاف التطبيق لموظف الكاشير بإظهار أدوات البيع والوردية والفواتير المسموح بها، مع منع الوصول لأي قسم دون صلاحية.

### 4. إعدادات الكاشير
- إضافة قسم واضح داخل الإعدادات للعملة، ضريبة المبيعات، ونظام الربح.
- اعتماد `متوسط التكلفة` كنظام الربح الحالي، وتخزين الاختيار على مستوى المؤسسة ليكون موحدًا لكل الفروع.
- التحقق من صحة رمز العملة ونسبة الضريبة قبل الحفظ، وتحديث بيانات المؤسسة وواجهات البيع فورًا بعد الحفظ.
- تسجيل تغيير هذه الإعدادات في سجل العمليات، مع إبقاء التعديل للمالك والمسؤول فقط.

### 5. توحيد الربح والتقارير
- إضافة حقل إعداد طريقة الربح إلى المؤسسة بقيمة افتراضية `AVERAGE_COST`.
- تحديث حساب التقرير المؤمّن ليستخدم تكلفة الصنف المسجلة وقت البيع، وهي متوسط التكلفة المعتمد عند إنشاء الفاتورة، حتى لا تتغير أرباح الفواتير القديمة بعد تغير تكلفة المنتج.
- إبطال بيانات التقارير والبيع ذات الصلة بعد حفظ الإعدادات كي تظهر العملة والضريبة والأرباح الجديدة تلقائيًا.
- عرض طريقة احتساب الربح الحالية في التقارير لمن يملك صلاحية عرض الربح.

## البيانات والأمان
- إضافة migration لتوسيع إعدادات المؤسسة فقط، دون إنشاء كتالوج أو مبيعات منفصلة.
- الحفاظ على عزل المؤسسات وسياسات الوصول الحالية، وتقييد تعديل الإعدادات بسياسات المسؤول الحالية.
- الحساب النهائي للضريبة والتكلفة والربح يبقى خادميًا؛ واجهة الكاشير تعرض تقديرًا فقط قبل إغلاق الفاتورة.

## التحقق
- فحص TypeScript وESLint والاختبارات وبناء الإنتاج، والتحقق من عدم وجود أي `use-mobile.tsx`.
- اختبار تسجيل الدخول لدور كاشير ودور إداري ومسار البدء لكل منهما.
- اختبار شاشة البيع على هاتف صغير وسطح مكتب: مسح باركود، تغيير الكمية، فتح السلة، الدفع، وإغلاق الفاتورة.
- اختبار تغيير العملة والضريبة ثم التأكد من تحديث شاشة البيع والفاتورة والتقارير.
- فحص آخر سجل بناء بعد التعديلات وإصلاح أي خطأ ظاهر قبل الإنهاء.

## افتراضات معتمدة
- نظام الربح هو متوسط التكلفة.
- التحويل التلقائي إلى شاشة البيع يطبق على دور `CASHIER` فقط.
- نفس `/pos` هي نسخة الكاشير المتخصصة؛ لا يُنشأ كتالوج أو مخزون أو تطبيق بيانات منفصل.
